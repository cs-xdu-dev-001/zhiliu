# 知流设计说明

## 产品定位

知流是一个由Hermes Agent驱动的个人信息监测与智能简报系统。系统部署在个人VPS上，使用者通过手机或电脑浏览器管理关注主题，查看每日热点、论文摘要与历史简报。

知流负责需求配置、任务调度、结果入库和界面展示；Hermes负责联网检索、网页阅读、论文分析和摘要生成。系统不重复实现Hermes已有的Agent能力。

## 首版范围

### 用户界面

1. 登录：单用户登录，未登录不可访问任何情报数据。
2. 首页：展示今日热点、本周论文、未读数量和最近任务状态。
3. 情报流：按热点、论文和招聘分类，支持已读、收藏、忽略和打开原文。
4. 订阅管理：维护名称、类型、关键词、执行周期、Hermes提示词和启用状态。
5. 定期报告：查看日报、周报及历史记录。
6. 任务状态：展示上次执行、下次执行、耗时、状态和错误摘要，支持手动触发。

### 非首版范围

- 多用户、角色和复杂权限
- 通用爬虫平台
- 自建RAG和向量数据库
- 复制PulseBoard的可观测能力
- 复杂工作流编排器
- 知识库全量同步；首版只保留后续接入KnowFlow AI的边界

## 系统架构

```text
手机/电脑浏览器
        |
      HTTPS
        |
      Nginx
        |
  React前端 + FastAPI后端
                 |
              SQLite
                 |
       Hermes API 127.0.0.1:8642
                 |
      Web检索、论文阅读、总结
```

前端采用React、TypeScript和Vite，按移动端优先设计。后端采用FastAPI和SQLAlchemy，数据库使用SQLite。单机单用户场景不引入MySQL、Redis或消息队列。

## Hermes集成

1. 后端从环境变量读取`HERMES_BASE_URL`和`HERMES_API_KEY`。
2. 调度器根据订阅周期创建执行记录，并调用Hermes异步Run接口。
3. 提示词要求Hermes返回约定JSON，包含标题、摘要、原文地址、来源、发布时间、关键词、推荐理由和重要性分数。
4. 后端轮询Run状态，校验结果后按原文URL与标题指纹去重入库。
5. Hermes不可用、超时或返回格式错误时，记录失败原因，不覆盖已有情报。
6. 开发环境支持演示数据，不需Hermes即可验证页面和业务流程。

## 数据设计

- `user`：单用户账号和密码哈希。
- `subscription`：订阅规则、提示词、周期和启用状态。
- `intelligence_item`：单条热点、论文或招聘情报。
- `briefing`：一次执行生成的日报或周报。
- `task_run`：每次调用Hermes的状态、耗时和错误信息。

## 安全与部署

- Hermes API仅监听`127.0.0.1`，不对公网开放。
- 公网只开放Nginx的80/443端口，强制HTTPS。
- 密码使用Argon2或bcrypt哈希，登录状态使用HttpOnly Cookie。
- Hermes密钥只存在服务器环境变量中，不返回前端，不写入Git。
- 通过Docker Compose运行前端、后端和Nginx，SQLite文件挂载到持久化目录。
- 服务器建议部署到`/opt/zhiliu`。

## 错误处理

- 任务调度防止同一订阅重叠执行。
- Hermes调用设置连接和整体超时，最多自动重试一次。
- 格式校验失败时保留Hermes原始响应摘要，便于排查。
- 外部原文无法访问不影响已入库摘要的查看。

## 验收标准

1. 手机和桌面浏览器均可完成登录、浏览、筛选和订阅管理。
2. 可创建、编辑、暂停和手动触发订阅。
3. 演示模式可完整展示情报流、简报和任务状态。
4. 配置Hermes后，手动触发可产生并入库一次真实结果。
5. 同一URL的结果不重复入库，失败任务有可读错误信息。
6. Docker Compose启动后可通过Nginx访问，重启后数据保留。
